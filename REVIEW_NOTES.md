# Review resolution

Independent local QA iteratively checked real progression, persistence, semantic identity, grading mutations and authentic Zen runtime. A separately authorized Claude Code read-only static review received only a supplied extension code/test/curriculum bundle; tools, MCP, customizations and session persistence were disabled. It did not execute tests.

Confirmed findings addressed after that review:

- Gate track switches/reloads request fresh work when the saved lesson was completed, preventing reuse of stale completion.
- Review scheduling is anchored to qualifying evidence/reviews rather than every routine check; daily practice can now reach retention. Retention requires qualifying, non-recently-assisted review evidence and keeps its earliest valid baseline across retests.
- Explicit four-decimal/fraction instructions and matching tolerance also cover intermediate calculations.
- Invariant residues, workload capacities, relative-order symmetry cases and variance scales vary; constant-answer memorization is reduced.
- Failed/malformed AI requests do not mark an item assisted. Only committed valid teaching does.
- A storage retry reuses an event ID only for an unchanged payload; edited answers get a fresh ID.
- Guided steps have guided labels, overlong inactive attempts do not fabricate an hour of activity, and invalidated completions no longer count in the dashboard header.
- Documentation uses lesson IDs rather than implying separate-day sessions, and generated hints/representative examples match current parameters.

Scope and remaining boundaries:

- The Python runtime is a local learning tool, not a hostile-code or anti-cheating security boundary. Python has Pyodide's JavaScript bridge and the browser owner controls extension storage/code. A deliberately malicious learner can spoof worker messages or alter their own evidence. Fresh submission namespaces prevent accidental reuse of previous functions, but do not provide complete process isolation from deliberate runtime monkey-patching. No claim of adversarial integrity is made.
- The retired generic Python mentor/review paths retain legacy model-dependent behavior, including historical challenge-issue handling; the current Quant Coding route uses checked local exercises and does not expose those legacy Help/Skip/review controls. Quant tutor prose cannot award mastery or decide unlocks.
- Provider model IDs and the existing remote Pyodide loading path were not redesigned. No in-extension paid AI call was made during validation. Remote runtime availability and standard Firefox compatibility remain explicit verification limits.
- The bounded curriculum and readiness thresholds are transparent design heuristics, not a validated certification of trading competence. Reassessment is labelled separately from novel evidence.

No Amos Learn code or prompts were identified as imported in the tracked changes. See ATTRIBUTION_AUDIT.md for scope and the limitation that no full upstream snapshot was available for a verbatim comparison.
